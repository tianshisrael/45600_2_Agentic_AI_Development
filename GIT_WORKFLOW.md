# Рабочий процесс Git (Git Workflow) для курса Agentic AI Development

Данное руководство описывает пошаговый процесс работы с репозиторием по схеме **Fork + Upstream**. Архитектура построена на четком разделении ролей между веткой-зеркалом (`main`), которая используется только для синхронизации с материалами преподавателя, и вашей изолированной рабочей веткой (`final-project`), где ведется разработка финального проекта.

---

## Конфигурация удаленных репозиториев
* **`origin`** — ваш личный удаленный репозиторий на GitHub (`tianshisrael/45600_2_Agentic_AI_Development`). Сюда у вас есть полные права на запись (`push`).
* **`upstream`** — оригинальный репозиторий преподавателя (`galamo/45600_2_Agentic_AI_Development`). Отсюда вы только скачиваете (`fetch`) обновления.

---

## 1. Ежедневная работа (Разработка проекта)
Вы находитесь в ветке `final-project`, пишете свой собственный код, настраиваете автоматизации и сохраняете изменения в свой удаленный репозиторий на GitHub.

```bash
# Проверить статус файлов (какие изменены, какие добавлены, что не отслеживается)
git status

# Добавить все измененные и новые файлы в индекс для отслеживания
git add .

# Зафиксировать изменения в истории проекта (создать локальный коммит)
git commit -m "Описание выполненной работы (например: Настроил интеграцию с ИИ-агентом)"

# Отправить сохраненные изменения в свой GitHub (в ветку final-project)
git push origin final-project
```

---

## 2. Синхронизация с репозиторием учителя
Когда преподаватель выкладывает новые лекции, лабораторные работы или обновляет общую базу курса, их необходимо сначала скачать в вашу локальную ветку-зеркало `main`.

```bash
# 1. Переключиться на ветку-зеркало курса
git checkout main

# 2. Скачать свежие данные и ветки из оригинального репозитория учителя (upstream)
git fetch upstream

# 3. Слить скачанные обновления в вашу локальную ветку main
git merge upstream/main

# 4. Отправить обновленную ветку main в свой личный профиль GitHub (origin)
git push origin main
```

---

## 3. Интеграция обновлений в ваш проект
После того как локальная ветка `main` успешно обновлена, вы можете перенести новые учебные материалы в вашу рабочую ветку `final-project`.

### Вариант А: Перенос всех обновлений курса целиком (Обновление базы)
Применяется, если учитель обновил общую конфигурацию, глобальные зависимости проекта или исправил критические баги в общих модулях курса, на которые опирается ваш код.

```bash
# 1. Вернуться в рабочую ветку вашего финального проекта
git checkout final-project

# 2. Влить все новые материалы из ветки main в текущую ветку проекта
git merge main
```

### Вариант Б: Точечный перенос конкретного файла или папки
Применяется, если вам нужна только папка с конспектом определенного урока или конкретный демонстрационный скрипт, и вы не хотите смешивать другие новые файлы учителя с архитектурой вашего проекта.

```bash
# 1. Убедиться, что вы находитесь в рабочей ветке проекта
git checkout final-project

# 2. Скопировать конкретную папку или файл напрямую из ветки main
# Внимание: двойное тире (--) обязательно
git checkout main -- путь/к/нужной_папке/
# Пример для отдельного файла: git checkout main -- lab_1/script.js

# 3. Зафиксировать появление новых файлов в истории вашей рабочей ветки
git add .
git commit -m "Точечно подтянул материалы лекции из ветки main"
```

---

## 4. Навигация и проверка состояния репозитория
Команды для контроля окружения, если необходимо проверить текущую активную ветку или настройки удаленных серверов.

```bash
# Посмотреть список всех локальных веток (текущая активная ветка всегда отмечена звёздочкой *)
git branch

# Проверить конфигурацию удаленных репозиториев (убедиться, что ссылки origin и upstream на месте)
git remote -v
```
